# Intent Classifier — ML Module

A lightweight, non-LLM intent classifier for the Elderly Care application.
Uses **TF-IDF + Logistic Regression** to identify the user's intent from a
natural-language question, without ever receiving patient medical data.

---

## Architecture

```
User Question
     │
     ▼
predict.py  (TF-IDF + Logistic Regression)
     │
     ├── intent
     └── confidence
          │
          ▼
   Node.js Backend
   (queries MongoDB and builds a safe, factual response)
```

---

## Setup

### 1. Install Python dependencies

```bash
cd ml/intent-classifier
pip install -r requirements.txt
```

Dependencies:
- **pandas** — CSV loading
- **scikit-learn** — TF-IDF vectoriser + Logistic Regression
- **joblib** — model serialisation

No TensorFlow, PyTorch, transformers, Ollama, or other LLM frameworks are used.

---

## Training

```bash
python train.py
```

This will:
1. Load `data/intents.csv`
2. Validate that `text` and `intent` columns exist
3. Remove empty/invalid rows
4. Split data 80/20 with a fixed `random_state=42` (reproducible)
5. Fit a `TfidfVectorizer` (unigrams + bigrams, max 5000 features)
6. Train a `LogisticRegression` classifier
7. Print accuracy and a per-intent classification report
8. Save `models/intent_model.joblib`
9. Save `models/tfidf_vectorizer.joblib`

---

## Prediction

```bash
python predict.py "Is mom taking her medicines on time?"
```

Expected output (stdout, JSON only):

```json
{"intent": "medicine_timing", "confidence": 0.94}
```

For a low-confidence or out-of-scope question:

```json
{"intent": "unknown", "confidence": 0.31}
```

### Exit codes

| Code | Meaning |
|------|---------|
| 0    | Success — valid JSON printed to stdout |
| 1    | Failure — error printed to stderr |

### Stdout rule

`predict.py` outputs **only the JSON result** on stdout.  
All diagnostic messages go to stderr.  
This makes it safe for Node.js `child_process.spawn` to parse the output.

## Dataset format

`data/intents.csv` is a two-column CSV:

```csv
text,intent
"Did mom take her medicine today?",medicine_today
"Is her BP increasing?",bp_trend
```

| Column   | Description |
|----------|-------------|
| `text`   | Natural-language question (no patient-specific data) |
| `intent` | One of the known intent labels |

### Known intents

| Intent | Meaning |
|--------|---------|
| `medicine_today`   | Did she take today's medicines? |
| `medicine_missed`  | Which medicines were missed/skipped? |
| `medicine_timing`  | Is she taking medicines on time? |
| `medicine_pattern` | What is her overall adherence pattern? |
| `sugar_trend`      | How has her blood sugar been? |
| `bp_trend`         | How has her blood pressure been? |
| `weight_trend`     | How has her weight changed? |
| `health_summary`   | Give a general recent health overview |
| `unknown`          | Returned by predict.py for low-confidence questions |

---

## Model architecture

| Component | Detail |
|-----------|--------|
| Vectoriser | `TfidfVectorizer` (unigrams + bigrams, max 5000 features, `sublinear_tf=True`) |
| Classifier | `LogisticRegression` (`C=5.0`, `max_iter=1000`, `solver=lbfgs`) |
| Serialisation | `joblib.dump / joblib.load` |

---

## Confidence threshold

The threshold is defined as a constant at the top of `predict.py`:

```python
CONFIDENCE_THRESHOLD = 0.70
```

If the predicted probability is below this value, the intent is returned as
`"unknown"` regardless of the predicted class.  Adjust this value after
validating against held-out questions.

---

## Privacy constraint

The ML model receives **only the raw question text**.  
It never receives:
- Patient profiles
- Medication lists
- Health records
- Medicine logs
- Blood pressure or sugar data

Intent classification and patient data retrieval are two completely
separate responsibilities.
